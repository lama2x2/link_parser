## 5. Найденные дефекты

Итого: **3**. Все выявлены при прогоне на реальном корпусе, автотестами не покрыты.

### Баг 1. Нет фолбэка HEAD → GET

Ссылка помечается битой, если сервер отвечает 404 на `HEAD`, но 200 на `GET`.

Пример: `https://www.figma.com/design/6tajpyASvzCUJziXVmqB6f/Wiki?node-id=0-1`

```
HEAD → 404
GET  → 200
```

Ссылка живая, в отчёте — `BROKEN`. Ложное срабатывание. Лечится повторным запросом методом GET при коде 403/404/405.

### Баг 2. Флаг `--no-check-anchors` игнорируется

При явном `--no-check-anchors` проверка якорей всё равно выполняется, в отчёт попадают 9 предупреждений.

### Баг 3. HTML-якоря не распознаются

Якоря, заданные как `<a id="...">` внутри заголовка, не учитываются при резолве.

```markdown
## <a id="migrations-politic">Политика миграций</a>
```

Ссылка `#migrations-politic` помечается ненайденной. Даёт 8 ложных предупреждений на файле `migration_policy.md`.

**Итог по точности:** из 4 сообщений `BROKEN` подтвердились 3, одно ложное. Из 10 предупреждений подтвердилось 2, восемь ложных.

CLI пишет туда поле `usage` из каждого ответа API. Скриптом `~/.claude/tools/cc_metrics.py`:

```bash
python3 ~/.claude/tools/cc_metrics.py <путь-к-.jsonl>
```

Промпты человека отделены от tool-результатов по признаку `origin.kind == "human"`. Записи с одинаковым `message.id` дедуплицированы, иначе `usage` считался бы дважды.

**Размер спецификации:**

```bash

```

**Эталон для проверки корпуса** посчитан независимым скриптом: разбор ссылок, percent-декодирование, резолв относительно файла-контейнера, проверка существования на диске; внешние ссылки — `curl` с браузерным User-Agent, follow-redirects и фолбэком HEAD → GET.
